# تبسيط خدمة الحجز — الإقامة والمواعيد (تصميم مقترح)

القرارات من المالك (2026-10-07): نبسّط **الإقامة** و**المواعيد** أولًا، **العيادات تبقى منفصلة** (جدولها `clinic_appointment_slots` ومساراتها كما هي).
مبني على: مراجعاتنا السابقة لـ booking.com / Airbnb / Vezeeta في [ux-references.md](ux-references.md) (قسم 2 و3 و5) + بحث 2026-10-07 في أنظمة الـPMS/Channel Managers وأنظمة المواعيد.

## 1) الفكرة الأم
**الحجز = صنف منيو + جدول.** الصنف نفسه (اسم، صور، سعر، خيار «السطر» وخيارات «المعدِّلات») ويتضاف له قسم «التوفّر». المحرك بيتحدد من نمط الحجز (`BookingPattern`) اللي موجود أصلًا:

| النمط | المحرك | مثال |
|---|---|---|
| `stay` | محرك الإقامة (ليالي + مخزون) | فندق، شقة، منتجع |
| `appointment` | محرك المواعيد (فتحات زمنية) | كوافير، حرفي، محامي |
| `consultation` عيادة | **كما هو** (منفصل) | عيادات |
| باقي الأنماط (طاولة، مدة، دورة) | تبقى كما هي الآن، تُنقل لاحقًا | — |

## 2) نموذج الإقامة (مأخوذ من نموذج الـPMS)
المرجع الصناعي: **نوع الغرفة × خطة السعر × مخزون × قيود** ([SiteMinder](https://help-classic.siteminder.com/en/articles/8673869-channel-manager-inventory-management-with-rate-plans), [شرح Rate Plans](https://www.smartorder.ai/resources/blog/rate-plans-hotel-channel-managers-how-they-work-how-many-you-need/)).

- **نوع الغرفة = صنف منيو**: خيار السطر = «غرفة مزدوجة/جناح…»، `capacity` ضيوف، `quantity` عدد الغرف من هذا النوع (المخزون)، صور وسمات (إطلالة، سرير).
- **خطة السعر = معدِّلات على نفس الصنف** (شامل الإفطار، قابل للإلغاء…): موجودة عندنا فعلًا (`offering_options` وسمة الوحدة مقابل اختيار الضيف). نفس المخزون يُغلق عبر كل الخطط — قاعدة الصناعة: لو بيعت الغرفة بخطة تُغلق في الباقي.
- **تقويم الليالي (جدول واحد بدل جدولين):** لكل (صنف، تاريخ): سعر مخصّص، مخزون مخصّص، والقيود القياسية: أقل/أقصى مدة إقامة، **إغلاق الوصول**، **إغلاق المغادرة**، **إيقاف البيع**، أقل/أقصى أيام قبل الوصول ([قيود الفنادق](https://help.lsretail.com/lscentral270/Content/LS-Hospitality/LS-Hotels/Restrictions.htm)). يحل محل `bookable_item_price_rules` + `bookable_item_blocked_slots` بواجهة واحدة للتاجر (شبكة أيام).
- **التوفر:** مخزون الليلة = `quantity` − الحجوزات الحية المتداخلة، لكل ليلة في الفترة.
- **البحث (تجربة booking.com):** تواريخ + عدد ضيوف كوحدة واحدة ← أنواع الغرف المتاحة مع «يبدأ من» بإجمالي الإقامة + زر الحجز. جدول أنواع الغرف (اسم، أسرّة، سعة، سعر) وليس سعرًا واحدًا للفندق.

## 3) نموذج المواعيد (مأخوذ من أنظمة الجدولة)
المرجع: Provider + Schedule أسبوعي + Overrides + AppointmentType + Appointment ([مثال تصميم](https://www.techinterview.org/post/3233466625/lld-appointment-scheduling/), [Buffer time](https://help.makeplans.com/article/92-buffer-time-between-appointments)).

- **الخدمة = صنف منيو** له `duration_minutes` و`buffer_minutes` اختياري.
- **ساعات العمل** موجودة عندنا (`business-working-hours`، أسبوعي مع فترات متعددة في اليوم) + **استثناءات** (إجازة/ساعات خاصة ليوم معين) — الجديد الوحيد.
- **توليد الفتحات:** مؤشر يتقدم بمدة الخدمة + الفاصل، يستبعد المتداخل مع حجوزات (مؤكدة/معلّقة) + الفاصل، ويحترم `lead_time_minutes` وأقصى مدة للحجز المسبق.
- **منع الحجز المزدوج:** قفل متشائم (`FOR UPDATE`) على حجوزات المورد في اليوم داخل معاملة، وإعادة فحص قبل الإدخال، وإن تغيّر الوضع: «الفتحة لم تعد متاحة» ([مثال](https://www.techinterview.org/post/3233466625/lld-appointment-scheduling/)). نفس القفل على صف الصنف في الإقامة.
- **تجربة العميل (Vezeeta):** تبويبات أيام + أزرار أوقات فعلية، ورسالة صريحة لليوم الخالي، وجملة سياسة الدفع («احجز أونلاين وادفع هناك»)، و«مدة الانتظار المتوقعة» لاحقًا.

## 4) ما الذي يتبسّط
- **شاشة واحدة للتاجر**: محرر الصنف (التسعير والتفاصيل) + قسم «التوفر» (تقويم ليالي أو ساعات عمل) بدل شاشات الحجز المنفصلة.
- **ملفات تُقسّم/تُحذف:** `ServiceExecutionEngine` (1887 سطر) → `StayEngine` و`AppointmentEngine` + تسعير وحجز مشتركين؛ `AdminV2/BookingController` (1597) يُستبدل بإدارة التاجر لحجوزاته من لوحته (لا صفحات إدارة جديدة).
- **جدولان بدل أربعة:** `bookable_items` ← `menu_items` (فيه 4 صفوف فقط الآن)، و`price_rules` + `blocked_slots` ← تقويم واحد.

## 5) الخطة
0. **التصميم** (هذا الملف) + قرارات المالك أدناه.
1. **واجهة التاجر**: قسم «التوفر» داخل محرر الصنف (بدون تغيير بيانات).
2. **الإقامة**: جدول التقويم + حساب التوفر + البحث بالتواريخ + اختبارات تنشئ بياناتها بنفسها.
3. **المواعيد**: ساعات + استثناءات + مولد الفتحات + القفل.
4. **ترحيل** `bookable_items` → `menu_items` (4 صفوف، رخيص) وحذف المسارات القديمة والصفحات المكرّرة.
كل مرحلة تُدمج مستقلة وبلا كسر، والعيادات لا تُلمس.

## 6) قرارات مفتوحة
1. **غرف فردية (رقم غرفة) أم عدد غرف لكل نوع؟** المقترح: العدد الآن، والغرف الفردية لاحقًا لو لزم.
2. **الدفع:** عند الحجز (عربون/كامل) أم في المكان؟ يتحدد لكل خطة سعر.
3. **سياسة الإلغاء:** لكل خطة سعر (قابل للإلغاء / غير قابل).
4. **التأكيد:** فوري أم بطلب يوافق عليه التاجر؟ (المقترح: فوري افتراضيًا للإقامة، وبطلب للمواعيد التي تحتاج تأكيدًا).
5. **المورد في المواعيد:** النشاط كله مورد واحد الآن (كوافير بكرسي واحد)، أم موظفون متعددون؟ المقترح: مورد واحد، والموظفون في مرحلة لاحقة (ثمّة نظام صلاحيات الموظفين جاهز).
